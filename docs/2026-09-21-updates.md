## Code Review Findings

Review scope: dead code, wiring gaps, and parity against upstream Python
(`/tmp/upstream`, `bhack/mini-eq`). The DSP core is in good shape — biquad
coefficients, `total_response_db`, `log_response_frequencies`,
`response_peak_frequencies`, and `estimate_response_peak_db` match upstream
exactly, including the Nyquist clamp and Q floor.

### Fixed this session

1. **Band selection was multi-select and never reached the graph.**
   Each `EqBandFader` set `selected = true` on click/keypress with no
   coordination, so several bands could render as selected at once, and
   `EqGraph::set_selected_band` had no callers at all. Selection is now owned by
   `window.rs`: the fader reports the clicked index, the owner clears every
   sibling and mirrors the choice into the graph. The callback is stored as
   `Rc<dyn Fn(usize)>` so handlers clone it out before invoking — the owner
   re-enters the fader to set `selected`, which would panic under a live
   `RefCell` borrow.

2. **Preset preamp was ignored in three places.**
   - The apply callback discarded `_preamp`; loading a preset left the previous
     preamp in place.
   - The reset callback reset bands but not the preamp (upstream
     `reset_state` zeroes both).
   - The state-signature callback hard-coded `0.0`, so preamp-only edits never
     marked the preset dirty.
   All three now read/write `HeadroomPanel::preamp_value()`.

3. **Inspector toggle button was unwired.** The header `ToggleButton` now drives
   `AdwOverlaySplitView::set_collapsed`.

4. **Formatting.** `window_graph.rs` and `window_headroom.rs` had pre-existing
   `cargo fmt` drift that would have failed CI; the tree is now clean.

### Reported, not fixed (need backend plumbing or are separate features)

- **GUI has no path to the audio backend.** `window.rs` never constructs
  `PipeWireBackend`/`RoutingEngine` and `WindowBandFader::new` passes a no-op
  `gain_changed_callback`. The graph re-reads fader state each tick, so the UI
  *looks* correct, but band edits are never applied to PipeWire. This is the
  highest-impact functional gap and needs a shared backend handle in the window.
- **`route_switch` ("System EQ") is unwired** for the same reason.
- **Output dropdown is a placeholder** — two hard-coded strings, not connected
  to `detect_routes()`.
- **`build_band_editor()` is a non-functional stub.** It builds Mute/Solo/Type/
  Freq/Q/Gain controls with no handlers and no link to the selected band. It is
  called, so it is not dead code, but it is inert.
- **`remove_link` is a stub** — it mutates the in-memory list only and never
  destroys the PipeWire link. `route_stream`/`unroute_stream` are no-ops.
- **Dead code with no non-test callers:**
  `analyzer.rs::{spectrum_db_values_to_levels,
  interleaved_f32le_bytes_to_channel_payloads, smooth_power_values}`,
  `window_presets.rs::set_bands_and_preamp`, and most of `routing.rs`
  (`with_auto_route`, `get_routes`, `get_active_route`, `get_current_sink`,
  `remove_link`, `get_links`, `route_stream`, `unroute_stream`,
  `get_virtual_sink_name`, `is_auto_route`, `set_auto_route`, `get_streams`,
  `unroute_from_virtual_sink`, `auto_route_all`, `get_virtual_sink_streams`,
  `get_routing_table`, `create_virtual_sink_stream`, `monitor_streams`) plus
  several `pipewire_backend.rs` accessors. These are the scaffolding for the
  unwired backend path; they should be kept and wired rather than deleted.
- `docs/BUGS.md` was stale (it claimed `core.rs` lacked functions that now
  exist); it has been refreshed.

## Push Status

**Blocked: the `GITHUB_TOKEN` in this environment cannot authenticate to GitHub
at all.** This is not a repository-permission problem — the GitHub App
installation for `mrproject72/mini-eq` has read/write on contents, which is what
a push needs. The failure is the credential itself:

- The token is a 40-char `ghu_...` user-to-server (GitHub App) token.
- `curl -H "Authorization: Bearer $GITHUB_TOKEN" https://api.github.com/user`
  returns `401 {"message": "Bad credentials"}`. A live App user-to-server token
  would return `200` here. These tokens expire after ~8 hours, so this one is
  stale.
- `gh auth status` agrees: "The token in GITHUB_TOKEN is invalid".
- Write attempt:
  `git push https://x-access-token:$GITHUB_TOKEN@github.com/...` →
  `remote: Invalid username or token. Password authentication is not supported
  for Git operations.`
- No SSH key (`~/.ssh` empty), no `~/.git-credentials`, no credential helper and
  no proxy configured, so there is no alternative auth path in this container.

**False lead worth recording:** `git ls-remote https://<token>@.../mini-eq.git`
succeeds and prints `ac53e0c`, which looks like the token authenticating reads.
It is not — `mrproject72/mini-eq` is a **public** repository (unauthenticated
`GET /repos/mrproject72/mini-eq` returns `200`, and `ls-remote` with no
credential succeeds too). The success was anonymous read access. Only a
write/auth-only endpoint reveals the token is dead.

### To unblock

Provide one of:

1. A classic PAT with `repo` scope, or a fine-grained PAT with

   `GITHUB_TOKEN` secret. A fresh App user-to-server token also works if the
   integration can be made to mint one at push time.
