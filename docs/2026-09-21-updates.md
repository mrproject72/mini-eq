## Code Review Findings

Review scope: dead code, wiring gaps, and parity against upstream Python
(`/tmp/upstream`, `bhack/mini-eq`). The DSP core is in good shape — biquad
coefficients, `total_response_db`, `log_response_frequencies`,
`response_peak_frequencies`, and `estimate_response_peak_db` match upstream
exactly, including the Nyquist clamp and Q floor.

### Fixed this session

1. **Band selection was multi-select and never reached the graph.**
   Each `EqBandFader` set `selected = true` on click/keypress with no
   coordination, so several bands could render as selected at once, and
   `EqGraph::set_selected_band` had no callers at all. Selection is now owned by
   `window.rs`: the fader reports the clicked index, the owner clears every
   sibling and mirrors the choice into the graph. The callback is stored as
   `Rc<dyn Fn(usize)>` so handlers clone it out before invoking — the owner
   re-enters the fader to set `selected`, which would panic under a live
   `RefCell` borrow.

2. **Preset preamp was ignored in three places.**
   - The apply callback discarded `_preamp`; loading a preset left the previous
     preamp in place.
   - The reset callback reset bands but not the preamp (upstream
     `reset_state` zeroes both).
   - The state-signature callback hard-coded `0.0`, so preamp-only edits never
     marked the preset dirty.
   All three now read/write `HeadroomPanel::preamp_value()`.

3. **Inspector toggle button was unwired.** The header `ToggleButton` now drives
   `AdwOverlaySplitView::set_collapsed`.

4. **Formatting.** `window_graph.rs` and `window_headroom.rs` had pre-existing
   `cargo fmt` drift that would have failed CI; the tree is now clean.

### Reported, not fixed (need backend plumbing or are separate features)

- **GUI has no path to the audio backend.** `window.rs` never constructs
  `PipeWireBackend`/`RoutingEngine` and `WindowBandFader::new` passes a no-op
  `gain_changed_callback`. The graph re-reads fader state each tick, so the UI
  *looks* correct, but band edits are never applied to PipeWire. This is the
  highest-impact functional gap and needs a shared backend handle in the window.
- **`route_switch` ("System EQ") is unwired** for the same reason.
- **Output dropdown is a placeholder** — two hard-coded strings, not connected
  to `detect_routes()`.
- **`build_band_editor()` is a non-functional stub.** It builds Mute/Solo/Type/
  Freq/Q/Gain controls with no handlers and no link to the selected band. It is
  called, so it is not dead code, but it is inert.
- **`remove_link` is a stub** — it mutates the in-memory list only and never
  destroys the PipeWire link. `route_stream`/`unroute_stream` are no-ops.
- **Dead code with no non-test callers:**
  `analyzer.rs::{spectrum_db_values_to_levels,
  interleaved_f32le_bytes_to_channel_payloads, smooth_power_values}`,
  `window_presets.rs::set_bands_and_preamp`, and most of `routing.rs`
  (`with_auto_route`, `get_routes`, `get_active_route`, `get_current_sink`,
  `remove_link`, `get_links`, `route_stream`, `unroute_stream`,
  `get_virtual_sink_name`, `is_auto_route`, `set_auto_route`, `get_streams`,
  `unroute_from_virtual_sink`, `auto_route_all`, `get_virtual_sink_streams`,
  `get_routing_table`, `create_virtual_sink_stream`, `monitor_streams`) plus
  several `pipewire_backend.rs` accessors. These are the scaffolding for the
  unwired backend path; they should be kept and wired rather than deleted.
- `docs/BUGS.md` was stale (it claimed `core.rs` lacked functions that now
  exist); it has been refreshed.

## Session 2 - selected-band editor and the mute model

### Task 4: functional selected-band editor

`window_layout.rs::build_band_editor()` was the stub described above: it built
M/S toggles and Type/Freq/Q/Gain controls, appended them, and returned - no
signal handlers, no link to the selected band. It has been replaced by
`src/window_band_editor.rs` (a real view over the selected fader) and removed
from `window_layout.rs`.

- `BandEditor::new(BandEditorCallbacks)` builds the editor row;
  `refresh(Option<&EqBandFader>)` repopulates it, mirroring upstream
  `update_selected_band_editor` - including the no-selection branch ("No Band",
  placeholder 1000 Hz, `DEFAULT_BAND_Q`, controls insensitive).
- Six callbacks (frequency/q/gain/filter_type/mute/solo) write through to the
  fader registry in `window.rs` and re-render the fader. Filter-type changes also
  re-derive `fader.active`, because upstream computes `active` as
  `filter_type != Off` rather than storing it.
- An `updating` guard mirrors upstream `updating_ui` so programmatic repopulation
  does not echo back through the change handlers as user edits.
- Styling follows upstream `style.css`: band-editor, band-editor-title,
  band-editor-selected, band-editor-state, band-editor-field, band-editor-input,
  band-editor-toggle (+ :checked), and metric-title, with the
  --mini-border-subtle / --mini-toggle-checked-* / --mini-text-dim variables added
  to `style.rs`.
- Upstream uses `Adw.WrapBox` here, which needs libadwaita 1.7; the pinned
  `adw 0.9.2` (features v1_4, v1_5) does not expose it, so a plain horizontal
  `gtk4::Box` carries the same controls.

### Re-entrancy fix (would have panicked on first edit)

The handlers were written as `if let Some(index) = *index.borrow() { callback(..) }`.
On edition 2024 the scrutinee temporary lives until the end of the `if let`
(including the success arm), so the `Ref` was still held when the callback called
`refresh()` -> `borrow_mut()` on the same cell: `RefCell already borrowed`, on
every single edit. Rewritten as `let Some(index) = *index.borrow() else { return };`,
which drops the temporary before the callback. Verified with a standalone repro
against the same `RefCell` shape before and after the change.

### Mute vs. filter-type Off - data loss on preset round-trip

Found while wiring the M button. `EqBand` modelled one `enabled: bool` where
upstream has two independent concepts: `filter_type != Off` (active) and `mute`.
Consequences of the conflation:

- `eq_band_to_dict` wrote "mute": !enabled, so an Off band and a muted Bell band
  serialised to the same JSON. A muted band reloaded unmuted - silent data loss on
  every preset save/load.
- `band_is_effective` ignored mute entirely (it tested `enabled && type != Off`),
  so a muted band still filtered audio.

`EqBand` now carries `pub mute: bool`, matching upstream. `band_is_effective` is
`!mute && filter_type != Off && (!solo_active || solo)`, the dict writers/readers
use `mute` verbatim, and legacy presets from this port that stored `enabled` still
load (inverted). `test_muted_band_roundtrips_through_preset` covers the regression.

The preset-apply path also mapped `enabled = band.enabled` / `muted = !band.enabled`
into the fader, which inverted mute for Off bands; it now uses `filter_type != Off`
and `band.mute`. Reset no longer carries a stale `solo_active` forward.
