## What this session did

by the previous session and resolved the question it was asking:

**The headroom/Auto-Safe peak estimate was using the graph-clamped response.**
`estimate_response_peak_db` clamped at +36 dB (display range), so stacked
boosts (4× HiShelf @ +20 dB → true peak ~+84 dB) were masked and Auto-Safe
under-compensated. Upstream passes `clamp_output=False` for this call.

Fix: split `total_response_db` into an unclamped core + clamped wrapper;
`estimate_response_peak_db` (and its frequency-list variant) now use the
unclamped path. Graph/autoeq rendering still use the clamped API. Probe test
replaced with a real assertion test. See `2026-09-28-updates.md`.
