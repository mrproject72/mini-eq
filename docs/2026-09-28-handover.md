## The smooth saga — read this before touching Smooth

The user's requirement, in their words:

> "the minimum should mimic the bell effect confined to one band; when
> width increases the bell effect expands through other frequencies but it
> ends at the base within the other bands level set, never lower, so that
> the curves stay rounded with no waves effect."

**The key realisation: Q is a filter-domain parameter; the user was
describing a curve-domain property.** Every attempt to express the
requirement as a Q/width lost the meaning. Four models were tried and
rejected before the right one:

| attempt | why it failed |
|---|---|
| Fixed `Q = 0.55` | measured on one isolated bump; wrong for multi-band sums |
| Width `0.5..4.0` oct | allowed the underlap zone -> 11 troughs |
| Floor at 1.05 oct | still 9 extrema; 2% kernel tail dragged 7 bands |
| `sigma = width / spacing` | coupled the two so narrow-local operation was unreachable |

**What shipped:** an integer-ish **spread** control (Gaussian sigma in
bands) with the bell Q derived and floored at the bridging width.

| slider | bands that move |
|---|---|
| `SMOOTH_SPREAD_MIN_BANDS = 0.45` | **1** — only the dragged band |
| `SMOOTH_SPREAD_DEFAULT_BANDS = 0.8` | 3 |
| `SMOOTH_SPREAD_MAX_BANDS = 3.0` | 9 |

Verified: 1 extremum across the whole spectrum at every position, and the
peak lands on the dragged band's own frequency at minimum spread.

**Key functions (`src/core.rs`):** `band_spacing_oct`,
`smooth_bell_q`, `smooth_kernel_weights`, `smooth_effective_band`,
`q_for_smooth_width` + `SMOOTH_WIDTH_TABLE`.

**The override never mutates stored state.** `smooth_effective_band()`
returns a modified copy; faders keep their own type/Q, so switching Smooth
off restores the user's settings exactly. `Off` bands stay `Off`.

**Still open on this:** the user's "never lower than the other bands'
level" is formally **monotone interpolation** (Fritsch–Carlson / PCHIP),
which makes waves impossible by construction rather than by tuning.
Verified numerically but **not implemented**, because the audio is a sum
of PipeWire biquads and the filter chain cannot compute `max()`. If
somebody revisits this, that's the reason it stopped.

## Auto-Safe: feed-forward only — do not make it live-driven

This was built, shipped, and **reverted in the same session.** Do not
re-attempt it without reading this.

Auto-Safe is `auto_safe_preamp_db(raw_peak, target) = (target −
curve_peak).clamp(EQ_PREAMP_MIN_DB, 0)`. It is **feed-forward**: the
curve peak is known in advance from the EQ settings, so the preamp is set
before any audio arrives.

A live-driven hybrid was tried. It **clips**, because:

| constraint | value |
|---|---|
| Auto-Safe UI tick | **33 ms** |
| Hard limiter in the PipeWire filter chain | **none** |
| Program transient length | **1–10 ms** |

A transient passes and clips before the feedback loop can observe it. The
user's own testing confirmed it: monitor off (feed-forward) = correct;
monitor on (live-driven) = clipping.

**Consequence users must understand:** Auto-Safe attenuates the whole
output by `1 dB + max EQ boost`. A +6 dB EQ costs 7 dB of output
(~62% perceived loudness). This is documented under **Known Issues** in
`docs/BUGS.md` as expected behaviour. Reclaiming that loudness requires a
sample-accurate limiter in the filter chain, not a faster UI loop.

## Gotchas learned this session

- **`Analyzer::take_window_peak()` consumes the value** (resets to 0).
  Read `monitor_peak_dbfs()` **once** per tick and reuse it.
- **`adw::WrapBox` is gated behind the crate feature `v1_7`.** Had to add
  it to `Cargo.toml`.
- **`connect_notify` requires `Send`** — capturing `Rc` needs
  `connect_notify_local`.
- **`gtk4::Box` has `insert_child_after(child, sibling)`, not
  `insert_child_before`.**
- **GTK4 does not auto-remove widgets from parents** — leave them unparented
  before reparenting.
- **`{:.2}` in Python is 2 *significant* digits, not 2 decimals** — this
  mislabelled a whole measurement table and led to a wrong default.
- **`cargo build --debug` is not a flag**; debug is the default.
- **Clippy rejects constant-value assertions** — assert real relationships.

These are **not** in Python mini-eq and should be called out explicitly:

- **Auto-Safe** (continuous preamp clamp) — upstream has only the one-shot
  `on_set_safe_preamp_clicked`

  internal filter type

- **Output control row** placement and the label-hiding responsive behaviour
- **Widened headroom budget** (-36 dB floor / +30 dB safe peak)

upstream, and biquad coefficients are asserted against upstream reference
values in the tests.
