# 2026-09-28 Updates

## Headroom/Auto-Safe peak estimate no longer clamped (upstream parity)

**Symptom (left as an open probe from the 2026-09-27 session):** with several
Hi-shelf bands boosted to +20 dB, Auto-Safe pushed the preamp to its −24 dB
floor yet the estimated peak after compensation still read +36 dB — the
clipping warning could never clear.

**Root cause:** `estimate_response_peak_db` sampled the curve through
`total_response_db_at_frequencies`, which applies the *graph-display* clamp
(`GRAPH_DB_MIN-12 .. GRAPH_DB_MAX+12` = −36..+36 dB). Four stacked +20 dB
shelves truly peak at ~+84 dB, but the estimate saw only +36 dB, so
`auto_safe_preamp_db` computed a target from a masked number. Upstream
avoids this by calling `total_response_db_at_frequencies(..., clamp_output=False)`
inside `estimate_response_peak_db` (core.py:1029).

**Fix (`src/core.rs`):**
- Added `total_response_db_unclamped()` (the raw dB computation) and
  `total_response_db_at_frequencies_unclamped()`.
- `total_response_db()` is now the clamped wrapper (graph rendering
  unchanged: `window_graph.rs`, `window_autoeq.rs` still get clamped values).
- `estimate_response_peak_db()` now uses the **unclamped** path, matching
  upstream `clamp_output=False`.

**Test:** replaced the throwaway `hishelf_autosafe_probe` with
`test_estimate_response_peak_db_is_unclamped` — asserts the 4×HiShelf peak
exceeds the +36 dB display clamp, a single +20 dB shelf measures ~23.5 dB,
and Auto-Safe correctly pins to `EQ_PREAMP_MIN_DB` (residual over-target is
expected: the preamp range cannot absorb +84 dB of boost, but the caller now
sees the real number).

74 lib tests pass, clippy clean, fmt clean.
