## Architecture comparison (Python original vs this Rust branch)

| Concern | Python original | Rust branch (before today) |
|---|---|---|
| EQ edits | `set_node_params()` pushes `SPA_PARAM_Props` to the **live** filter node — no reload, links survive. Filter-**type** changes call `restart_engine()` (topology). | Full module **reload per edit** → destroyed `mini_eq_sink` → severed every app→EQ link. |
| Stream routing | PulseAudio-compatible **default metadata** (`target.node`). | Manual `link-factory` links. |
| Spectrum | `OutputSpectrumAnalyzer`: `stream.monitor=true` capture tap + FFT reader thread. | **None** — update loop passed `&[]`. |
| Sidebar | No breakpoints. | Invented 1320sp breakpoint that force-collapsed the pane. |

## Fixed this session

1. **UI → backend pipeline connected** (`main.rs`, `window.rs`).
   `launch_gui` starts the filter-chain engine against the detected default
   physical sink and shares the backend with the window via
   `Rc<RefCell<Option<PipeWireBackend>>>`. The window's 33 ms update loop
   pushes band + preamp state (debounced 400 ms) to the engine.

2. **Live `SPA_PARAM_Props` control** (`pipewire_backend.rs::apply_live_controls`).
   Mirrors upstream `set_node_params`. A persistent registry listener captures
   the live `mini_eq_sink` `Node` proxy; edits build a `SPA_PARAM_Props` object
   whose `params` property (`SPA_Props_params` = `0x80000`) is a struct of
   alternating `(control-name, f64)` pairs (e.g. `band_l_0_filter:Freq`),
   pushed via `node.set_param()`. DSP updates in ms; graph/links survive.
   - The registry `Listener` is now **stored in the backend** — listeners
     unregister themselves when dropped, so the previous `let _ =` pattern
     silently stopped receiving events.

3. **Double-free in `unload_filter_chain_module`** (`pipewire_backend.rs`).
   `take()` + `pw_impl_module_destroy` + `ModuleHandle::drop` destroyed the
   same `pw_impl_module` twice → crash on the first band update. Fixed with
   `std::mem::forget` after destroying the raw pointer.

4. **Active bands default to Bell** (`window_layout.rs::build_band_faders`).
   Every fader was created with `FilterType::Off`. The window reads fader state
   and pushes it, so all pushed bands were Off → wet/dry mix 0 → biquad
   bypassed → dragging the fader changed gain on a bypassed filter (silent).
   Active bands (`i < DEFAULT_ACTIVE_BANDS`) now default to Bell, matching
   `core::default_bands()` and upstream. Inactive bands stay Off.

5. **Filter-type change now restarts the engine** (`pipewire_backend.rs`).
   Native biquad labels are graph **topology**, fixed at module-load time
   (`label = bq_peaking`), so they are not mutable live controls. The backend
   now tracks `engine_band_types` (the types the loaded module was built with);
   a type/preset mismatch triggers unload + reload (with the stale node proxy
   cleared so the registry listener re-captures the new node). Ordinary
   Freq/Q/Gain/mute/solo edits stay live. Mirrors upstream
   `set_filter_controls` / `_engine_band_types`.

6. **Graph overlay reflects the selected band** (`window.rs`).
   The update loop passed a hardcoded `FilterType::Bell` (and fixed 1000 Hz /
   Q 1.0) to `EqGraph::update`, so switching filter types never changed the
   drawn curve. It now passes the selected fader's actual frequency/Q/type.

7. **Sidebar no longer auto-collapses** (`window.rs`).
   The Rust-invented 1320sp narrow breakpoint called `set_collapsed(true)` on
   every layout re-evaluation (a click re-triggers it), making the right panel
   vanish. Removed the forced collapse; kept only the layout compaction.

8. **Real link-factory routing** (`routing.rs`).
   `create_link` was a memory-only stub. Ported real `link-factory`
   `create_object::<Link>` via `link_nodes()`, added roundtrip-pumped
   `find_node_id_by_name()` and `list_playback_streams()`
   (`media.class = Stream/Output/Audio`); `auto_route_to_sink()` now links
   actual app playback streams into the virtual sink.

## Session 2 (2026-09-27): Routing + output-target fixes

See `docs/PLAN/routing-and-output-architecture.md` for the full architecture.

### Fixed: System EQ now actually routes audio (default-metadata)
- Replaced the `link-factory` routing (overridden by WirePlumber) with
  **default-metadata `target.node`/`target.object`** writes, mirroring upstream
  `set_stream_target`. Bound the `default` metadata via
  `registry.bind::<Metadata,_>` on the global with `metadata.name=="default"`
  (`pw_core_get_metadata` is not exported by libpipewire 1.6 — do not extern it).
- `auto_route_to_sink` now sets each stream's target; `unroute_all` clears them
  (System EQ OFF). Wired the window's OFF branch to `unroute_all`.
- Verified live: `Routed 'fooyin' (96) -> mini_eq_sink (target.node=…, target.object=…)`.

### Fixed: "System EQ mutes audio" (wrong output target)
- Root cause: filter-chain playback node targeted the **Logitech USB headset**
  (a suspended device) because `default_output_sink()` used a broken
  `detect_routes()` that hardcoded `active:true` for every node. The passive
  output link stayed `paused` → mute.
- Portable fix: read the real default from the `default` metadata key
  **`default.audio.sink`** (JSON `{"name": …}`), parse via
  `parse_metadata_node_name`, use as the filter-chain `target.object`.
  Works on any PipeWire machine — no hardcoded device names.
- Verified live: `Loading filter-chain module -> alsa_output.pci-0000_04_00.6.analog-stereo`
  and `mini_eq_sink_output -> alsa_output.pci-…analog-stereo`.

### Gotchas hit
- A `Metadata`/proxy `property` listener is **unregistered when dropped** —
  stored it in `RoutingEngine::metadata_listeners`.
- The server replays metadata properties on bind; pump a few extra loop
  iterations after the roundtrip so `default.audio.sink` lands before reading.

### Build status
- `cargo build` clean, `cargo test --lib` 69 passed.

### Next

- Re-target filter output when `default.audio.sink` changes at runtime.
- Re-route after filter-type restart; add `node.dont-move`/foreign-target guards.

### Fixed: "Set Safe" / preamp didn't reduce actual output
- Root cause: the filter-chain **preamp node is a `bq_raw` node** whose gain is
  carried in the raw biquad coefficients (`preamp_l:b0`…`a2`), per upstream
  `builtin_biquad_preamp_control_values` → `biquad_coefficients_to_controls`.
  The Rust port pushed `preamp_l:Gain 1`/`Gain 2` (mixer controls that only
  exist on **band** nodes), so the live preamp write hit a non-existent control
  → graph lowered but DSP output unchanged.
- Fix: `native_biquad_preamp_control_values` now pushes `preamp_<side>:b0..a2`
  from `preamp_biquad_coefficients` (scaled for the ±10 control range). Added
  `biquad_coefficients_to_controls` helper. Updated `test_preamp_control_gain`.
- Two control schemes in the graph (do not mix them up):
  - **bands**: `band_<side>_<i>_filter:Freq/Q/Gain` + `band_<side>_<i>:Gain 1/2` (mixer wet/dry)
  - **preamp**: `preamp_<side>:b0..a2` (bq_raw coefficients)

### Added: Auto-Safe toggle (continuous preamp clamp)
- Verified upstream has NO auto-preamp toggle — "Set Safe" is one-shot only.
  This is a deliberate enhancement requested by the user.
- New "Auto-Safe" switch in the headroom panel. When ON, every 33ms tick
  recomputes the preamp so the curve peak stays at/below `AUTO_SAFE_TARGET_DBFS`
  (-1 dBFS): slide EQ up -> preamp auto-lowers; slide down -> preamp rises
  back toward 0 (never above 0 dB). Manual preamp slider is disabled while
  Auto-Safe owns the value.
- Pure fn `auto_safe_preamp_db(raw_peak_db, target_dbfs)` in
  `window_headroom.rs` (clamps to [EQ_PREAMP_MIN_DB, 0]). Applied in the
  window update loop before reading `preamp_db`.

### Fixed: Reset made the EQ inert (all bands Off)
- Reset callback hardcoded `filter_type = Off` for every band. Off bands
  contribute nothing, so the curve went flat and moving a fader did nothing
  ("EQ stays off").
- Upstream `reset_state` restores `default_bands()` (first
  DEFAULT_ACTIVE_BANDS as neutral *Bell*s). Now the reset callback uses
  `default_bands()` and applies each band's real filter_type -> after Reset
  the EQ is neutral (0 gain) but fully responsive.
- Reset lives in the Presets panel (right utility sidebar, "Reset" /
  "Reset to neutral"); F9 toggles the sidebar.

## Session 3 (2026-09-27): Overlay panel + minimum-window-size fixes

### Fixed: true overlay side panel (content always full width)
Verified the authoritative semantics from `deps/usr/share/gir-1.0/Adw-1.gir`
(class `AdwOverlaySplitView`):
- `collapsed=FALSE` -> sidebar and content **side by side** (content resized).
- `collapsed=TRUE`  -> sidebar shown as an **overlay above the content**
  (content stays FULL width).
- `show-sidebar`    -> whether that overlay is actually visible.
- `pin-sidebar=TRUE`-> visibility never changes on its own (we drive it).

Was: toggling `collapsed` flipped between side-by-side and overlay, so the
content resized / left empty space. Now:
- `collapsed=TRUE` always (overlay mode), `pin_sidebar=TRUE`,
  `show_sidebar=FALSE` by default -> main content uses the FULL width.
- The header toggle and F9 drive `show_sidebar` (F9 toggles the inspector
  button's active state as the single source of truth). Panel slides OVER
  the full-width content without shrinking it.

### Fixed: horizontal cutting at minimum window size (the real culprit)
Symptom: at min width the faders stayed "fat" and got cut, and the overlay
panel started OUTSIDE the window's right edge (enlarging the window
revealed it). Vertical resize was fine.

Investigated by measuring every widget's min width at runtime
(`widget.measure(HORIZONTAL, -1)`). Chain:
  toolbar=866  split=866  bandscroll=558  utility=389  graph=147
  **editor=866**  <-- the driver
Root cause: the **BandEditor** (bottom of the main content) was a single
non-wrapping horizontal row of fixed-width controls:
  title(88) + mute/solo + Type(118) + Frequency(110) + Q(82) + Gain(96)
  + labels => 866px minimum.
This forced main_box -> OverlaySplitView -> ToolbarView -> window to an
866px floor. The window could not shrink below 866; when forced smaller
the content clipped and the overlay panel (anchored to the content's right
edge) rendered outside the viewport.

Why vertical worked but horizontal didn't: the utility panel scrolls
vertically (ScrolledWindow vertical=Automatic -> min 58px) so it never
forced the window height. Horizontally the editor was a rigid row, so it
forced the width. (The faders were a red herring.)

Fixes:
- `window_band_editor.rs`: controls now `hexpand` with reduced min widths
  (Type 84, Freq 72, Q 56, Gain 66); `field()` shells `hexpand`;
  `title_box` `hexpand`; "Frequency" label shortened to "Freq". The row
  shrinks to fit instead of dictating an 866px floor.
- `band_fader.rs`: `set_height()` (called by the narrow/compact
  AdwBreakpoint) no longer resets the fader width to the fixed
  `CONTENT_W=72` — that re-widened the row exactly when the window got
  small. It now keeps the responsive `FADER_MIN_W` (44) and only changes
  height. Removed the now-unused `CONTENT_W`.
- Faders are horizontally responsive: `content_width=FADER_MIN_W`,
  `hexpand`, and the band row is `homogeneous`, so 10 faders share the
  available width (~64px each at 640px) instead of overflowing.

Verified: 0 `AdwToolbarView exceeds window width` warnings; window shrinks
freely to the 640x480 minimum. 70 lib tests pass, clippy/fmt clean.

### Method note (for future layout bugs)
When a GTK4 window "can't shrink" / content clips, don't guess — measure
each widget's minimum with `widget.measure(gtk4::Orientation::Horizontal,
-1)` at runtime (temporary `glib::timeout_add_local` block) and walk the
chain to the widest leaf. That is the floor. Here it was a single editor
row, not the faders or the sidebar.
